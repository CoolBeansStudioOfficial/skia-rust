# hb-subset port: what is covered and what is left

Branch `port/hb-subset`, crate `crates/skia-rust-hb-subset`, design in `docs/design/modules.md` §7.1. Entry point:
`skia_rust_hb_subset::subset_font(font_data, glyph_ids, ttc_index) -> Option<Vec<u8>>` (and `try_subset_font`, which tells a
HarfBuzz failure from a part that is not ported). It is not wired into `skia-rust-pdf` (port/pdf-m26 owns that).

## Verification state

- `oracle/subset-diff/` (C driver on HarfBuzz 9cb1fee5, Skia's defines): `corpus.txt` has 462 entries (every Skia resources
  font with outlines, nine glyph sets each, with and without glyph 0). 100% of the entries for fonts the PDF backend can
  reach are byte-identical; the four fonts in `NOT_PORTED` in `tests/subset_diff.rs` are unreachable from Skia (CFF/CFF2
  outlines and a variable font go to Type3, see §7.1).
- `oracle/subset-diff/synthetic/` (generated by `gen_synthetic.py`): eight fonts for hb-repacker's extension promotion,
  subtable splitting, shared-node duplication and priority raising; all identical, including two where HarfBuzz fails.
- Local-only extended corpus (`HB_SUBSET_EXT_DIR`, HarfBuzz test fonts and system fonts): 5672 exact entries.

## Not ported (listed exactly)

Reported as `SubsetError::Unsupported`; all unreachable from `SkPDFSubsetFont` (non-variable `glyf` fonts only):

1. `CFF ` and `CFF2` subsetting (`hb-subset-cff*.cc`, `hb-ot-cff*-table.hh`), `VORG`.
2. `HVAR`/`VVAR` and everything that writes an `ItemVariationStore` (`hb-ot-var-common.hh`, `hb-ot-layout-common.hh`
   `VarStore::serialize`): `GDEF` var store, `BASE` var store, `COLR` var store and `VarIdxMap`, `GSUB`/`GPOS`
   `FeatureVariations`. A static font with a `GDEF` var store is the one case here that a PDF could in principle reach; none
   is in any corpus.
3. The sanitizer (`hb-sanitize.hh` and every `sanitize()` method). `hb_face_t` tables that fail HarfBuzz's sanitizer make
   `hb-subset` return nothing; this port reads malformed tables with `Null` semantics and subsets them. Two fonts of the
   extended corpus (`HarfBust.ttf`, `NotoColrEmojiGlyf-Regular.subset.ttf`) differ for that reason. Every font in the committed
   corpus sanitizes.
4. hb-repacker: all of it is ported. The oracle fonts exercise: space assignment, isolation, shared-node duplication, priority
   raising, extension promotion (`make_extension`), `PairPos` 1/2, `MarkBasePos` 1 and `LigatureSubst` splitting. Not
   exercised by any font: `PairPos` format 2 splits that succeed in HarfBuzz (every synthetic attempt fails in HarfBuzz as well, so
   the cloned halves' bytes are not compared) and `PairPos` device tables in value records.
5. Deep recursion: `Graph::find_connected_nodes`/`find_subgraph` recurse like HarfBuzz's; a table with a connected graph of
   about 10^5 objects might need a larger stack than a 2 MiB test thread (the largest corpus table has 10^4).
